# Предложения по новому функционалу AuthorToday

Имея воронку, сравнение периодов, фоновую загрузку и MS SQL, ниже — идеи следующих фич.
Приоритет: польза для автора при анализе прочтений, без раздувания в «платформу».

---

## Высокая польза

### 1. Удаление run из UI

Кнопка с превью (какие `fetch_runs` / сколько `chapter_reads`) и подтверждением.
Сейчас только `scripts/delete_runs.py`. Уже упоминалось в docs как «не MVP», но закрывает боль дублей загрузок.

### 2. Календарь покрытия данных

По книге: какие дни есть в БД, где пропуски (логика `check_load_gaps` → таблица/график в Streamlit).
Опционально: «загрузить пропуски» одним действием.

### 3. Автозагрузка по расписанию

Раз в месяц (например, прошлый месяц) без UI: Windows Task Scheduler + CLI.
В UI — статус последних автозагрузок / ошибок.

### 4. Сравнение более чем двух периодов

A / B / C или «этот месяц vs средний за N месяцев».

## Аналитика

### 5. Точки провала воронки

Автоподсветка глав с наибольшим падением % от предыдущей и/или от базы.

### 6. Тренд дочитывания ✅

График «глава, % от базы» по месяцам для одной книги.
В UI: выбор книги и главы (по умолчанию последняя), skip «Страница книги» и база как у воронки.
Модуль: `analyze/completion_trend.py`, вкладка «Тренд дочитывания».

### 6a. Нужно грузить и другие метрики (time, avgTime) — частично ✅

Сейчас в БД есть `fetch_runs.value_type`; в UI «Загрузка» и CLI (`--value-type` / `--all-metrics`) можно грузить hit / time / avgTime.
Отчёты пока по умолчанию читают hit. Дальше: селектор метрики в воронке/сравнении/тренде.

Архитектура: [docs/metrics_value_types.md](docs/metrics_value_types.md).

### 7. Несколько книг рядом
Одна метрика (дочитывание / μ) по портфелю книг из `dbo.books`.

### 8. Алерты

Например: «за месяц дочитывание упало больше чем на X%» → сообщение в UI, файл или Telegram.

---

## Удобство

### 9. Сохранённые пресеты отчётов

Книга + периоды + base-order / skip-book-page в yaml или БД — открытие отчёта в один клик.

### 10. Merge multi-month CSV/JSON

Один файл на весь запрошенный период (сейчас при >1 месяца в `-o`/`--json` попадает только последний chunk + warning).

### 11. Заметки к периоду

Текстовые пометки вроде «реклама с 5-го», «новая обложка» рядом со сравнением периодов — контекст для Δμ / p-value.

---

## Не предлагать в ближайшее время

- Мультипользовательский доступ / Django / регистрация
- Продажи из `reclan.csv` — только если появится чёткая задача
- Отдельный HTTP API без реальной потребности (Streamlit достаточно)

---

## Рекомендуемый старт

1. **Календарь покрытия** + при желании догрузка дыр  
2. **Удаление run в UI**

Оба пункта сразу улучшают качество данных и снижают ручную работу со скриптами.
