# Предложения по новому функционалу AuthorToday

Имея воронку, сравнение периодов, фоновую загрузку и MS SQL, ниже — идеи следующих фич.
Приоритет: польза для автора при анализе прочтений, без раздувания в «платформу».

---

## Высокая польза

### 1. Удаление run из UI ✅

На вкладке «Загрузка»: expander «Удалить загрузку» — выбор `run_id`, превью числа `chapter_reads`, подтверждение.
Удаляются `fetch_runs` + связанные `chapter_reads` (`services/runs.py`, `MssqlReadRepository.delete_run`).

### 2. Календарь покрытия данных

По книге: какие дни есть в БД, где пропуски (логика `check_load_gaps` → таблица/график в Streamlit).
Опционально: «загрузить пропуски» одним действием.

### 3. Автозагрузка по расписанию

Раз в месяц (например, прошлый месяц) без UI: Windows Task Scheduler + CLI.
В UI — статус последних автозагрузок / ошибок.

### 4. Сравнение более чем двух периодов

A / B / C или «этот месяц vs средний за N месяцев».

## Аналитика

### 5. Точки провала воронки

Автоподсветка глав с наибольшим падением % от предыдущей и/или от базы.

### 6. Тренд дочитывания ✅

График «глава, % от базы» по месяцам для одной книги.
В UI: выбор книги и главы (по умолчанию последняя), skip «Страница книги» и база как у воронки.
Модуль: `analyze/completion_trend.py`, вкладка «Тренд дочитывания».

### 6a. Нужно грузить и другие метрики (time, avgTime) — частично ✅

Сейчас в БД есть `fetch_runs.value_type`; в UI «Загрузка» и CLI (`--value-type` / `--all-metrics`) можно грузить hit / time / avgTime.
Отчёты пока по умолчанию читают hit. Дальше: селектор метрики в воронке/сравнении/тренде.

Архитектура: [docs/metrics_value_types.md](docs/metrics_value_types.md).

### 7. Несколько книг рядом
Одна метрика (дочитывание / μ) по портфелю книг из `dbo.books`.

### 8. Алерты

Например: «за месяц дочитывание упало больше чем на X%» → сообщение в UI, файл или Telegram.

## Удобство

### 9. Сохранённые пресеты отчётов

Книга + периоды + base-order / skip-book-page в yaml или БД — открытие отчёта в один клик.

### 10. Merge multi-month CSV/JSON

Один файл на весь запрошенный период (сейчас при >1 месяца в `-o`/`--json` попадает только последний chunk + warning).

### 11. Заметки к периоду

Текстовые пометки вроде «реклама с 5-го», «новая обложка» рядом со сравнением периодов — контекст для Δμ / p-value.

### 12. Понятные ошибки при «чужой» / несуществующей книге (fetch)

Сейчас при странице без таблицы парсер ~45 с ждёт Kendo и падает с «Таблица статистики не найдена» — без различия причин.

**Типичные ответы сайта (текст на странице):**

| Ситуация | Текст на author.today (ориентир) | Смысл |
|----------|----------------------------------|--------|
| Нет прав | «В доступе отказано.» + «У вас недостаточно прав…» | Чужая книга / нет прав автора на отчёт |
| Нет страницы | «404. Страница не найдена» + «Страница устарела, была удалена…» | Неверный `book_id` / книга удалена |

**Как правильно реагировать:**

1. **Дождаться DOM после `driver.get`**, затем **сначала** проверить текст страницы (или стабильные CSS/заголовки ошибки), **потом** искать грид. Не тратить полный timeout на отсутствующую таблицу.
2. **Отдельные исключения** (например `AccessDeniedError` / `PageNotFoundError` или один `StatsPageError` с `reason=forbidden|not_found`), не общий `TimeoutException`.
3. **Сообщения пользователю** (UI баннер + CLI stderr) — явные и короткие:
   - forbidden: «Нет доступа к статистике этой книги (чужая или нет прав). Загружайте только свои произведения.»
   - not_found: «Книга/страница не найдена (404). Проверьте book_id.»
4. **Не писать в БД** за этот шаг (как сейчас при любой ошибке). Не создавать «пустой» `fetch_run`.
5. **Мульти-месяц / несколько метрик:** при forbidden/not_found **сразу остановить** всю job (повтор по следующим месяцам бессмысленен для того же `book_id`).
6. **Детекция по устойчивым фрагментам** (`"В доступе отказано"`, `"404. Страница не найдена"`), не по всему абзацу — вёрстка сайта может чуть меняться.
7. **Fallback:** если ни ошибка, ни грид — оставить текущее «таблица не найдена» (сеть, другая вёрстка, сессия).

**Где править:** `fetch/stats_page.py` (проверка после открытия URL) → узкий helper в `parse/` или `fetch/`; проброс через `FetchJob` / `sync_reads`; отображение уже есть через `status=error` + `progress.error`.

**Тесты:** unit на разбор HTML/текста фикстур (forbidden / 404 / нормальная страница с гридом); без живого Selenium.

**Приоритет:** высокий для UX загрузки; маленький объём работ.

## Не предлагать в ближайшее время

- Мультипользовательский доступ / Django / регистрация
- Продажи из `reclan.csv` — только если появится чёткая задача
- Отдельный HTTP API без реальной потребности (Streamlit достаточно)
