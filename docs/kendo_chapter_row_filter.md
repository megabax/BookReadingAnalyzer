# Фильтр строк Kendo: нужен ли белый список глав?

**Дата:** 2026-08-16  
**Контекст:** пропуск строки «Эпилог» при загрузке (book_id=20110 и аналоги); маркеры в `parse/kendo_grid.py`.  
**Вопрос:** можно ли отказаться от `CHAPTER_MARKERS` (whitelist по тексту названия)?

---

## Как устроены данные на сайте

Отчёт `/report/work/stats` — **Kendo Grid**:

- колонка с подписью строки (locked) — свободный текст автора/платформы;
- остальные колонки — даты `DD.MM` и числа метрики.

В HTML/JS **нет** семантического типа строки (`data-kind="chapter"` и т.п.). Есть только строковое поле названия.

Два пути извлечения:

1. **dataSource** (предпочтительный) — все items грида; в JS уже отбрасываются пустые и ровно `"Часть"`.
2. **DOM-scroll** (fallback) — те же подписи из ячеек; снова фильтр по тексту.

Белый список применяется **после** разбора HTML/JS, не вместо него.

---

## Что делает whitelist сейчас

```text
CHAPTER_MARKERS ≈ глава | интерлюдия | страница книги | эпилог | вместо эпилога | часть
```

Строка попадает в снимок, только если подпись содержит один из маркеров  
(плюс явный exception: `"Страница книги"` в `_table_row_allowed`).

Заголовок секции **`Часть`** (ровно это слово) отбрасывается отдельно — это не глава, а служебная строка сетки (иначе ломалось сопоставление locked/scroll).

---

## Проблемы whitelist

| Проблема | Следствие |
|----------|-----------|
| Неполный список жанровых/служебных названий | «Эпилог» не грузился, пока не добавили маркер |
| Неизвестные подписи («Пролог», «Послесловие», «Экстра», кастомные имена) | Тихо теряются при fetch |
| Ложное чувство полноты | В UI/БД кажется, что снимок полный |
| Дублирование логики | «Страница книги» и в маркерах, и отдельной веткой |

Польза whitelist сомнительна: шум в dataSource отчёта автора обычно = те же строки таблицы, что видит человек. Лишние «не-главы» кроме **`Часть`** на практике не наблюдались как отдельный класс строк с метриками.

## Можно ли отказаться?

**Да. Рекомендация: отказаться от белого списка.**

Заменить на **чёрный список служебных строк** (минимальный):

Принимать все непустые подписи **кроме**:

1. ровно `Часть` (регистр как на сайте / после `strip`; сравнение case-insensitive);
2. опционально — пустые / пробельные;
3. опционально позже — другие доказанные служебные ярлыки, если появятся.

Маркеры `CHAPTER_MARKERS` / `_is_chapter_label` для **сохранения в снимок** не нужны.

Оставить маркеры можно только как **необязательную** эвристику (например, предупреждение в логе: «необычное имя строки»), но не как условие записи в БД.

### Почему это безопасно для продукта

- Источник правды для отчётов — то, что сайт показывает в матрице; воронка и тренд должны видеть те же строки.
- Фильтр «убрать обложку» уже есть на уровне аналитики (`--skip-book-page` / `is_book_page`), а не парсера.
- Риск «лишней» строки в БД ниже риска **молчаливой потери** эпилога/пролога.

### Остаточные риски (принять)

| Риск | Оценка | Митигация |
|------|--------|-----------|
| Новая служебная строка на сайте (не «Часть») | Низкая | Чёрный список + known_issues; unit-тест на фикстуру |
| Строка без чисел по всем дням | Низкая | Можно не писать полностью пустые ряды (опционально) |
| DOM-путь подтянет мусор из других таблиц | Низкая при текущем выборе `.k-grid` | dataSource-first уже снижает риск |

## Предлагаемое правило (целевое)

```text
row_ok(name) :=
  name.strip() не пусто
  AND name.strip().casefold() != "часть"
```

Дальше — в `StatsTable` / `chapter_reads` без доп. whitelist.

Места правки: `_table_row_allowed`, `iter_scroll_row_indices`, `_extract_plain_table`, при желании упростить JS dataSource (там уже почти так).

---

## Миграция данных

Уже загруженные run'ы **не содержат** отброшенные строки. После смены фильтра:

1. удалить затронутые `fetch_runs` (UI или `delete_runs.py`);
2. перезагрузить периоды.

Только «добавить маркер эпилог» недостаточно для старых run'ов — то же относится к полному отказу от whitelist.

---

## Вердикт

| Вариант | Решение |
|---------|---------|
| Оставить whitelist и дописывать маркеры | Не рекомендуется (вечная гонка с названиями) |
| **Убрать whitelist, blacklist только «Часть» (+ пустые)** | **Рекомендуется** |
| Whitelist как warning, не как блок | Допустимый компромисс, не обязателен |

**Итог:** от белого списка можно и нужно отказаться; достаточно чёрного списка служебных подписей. Разбор HTML/Kendo при этом сохраняется.
